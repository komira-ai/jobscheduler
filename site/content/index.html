Early development open source, Apache 2.0

Leases on whole hosts, and a core that places work by load.

jobscheduler is a generic scheduler for jobs and compute. A client leases a host from a lease server for a bounded time and renews the lease while it needs it. An agent on each host tells the server what the host offers, keeps telling it that the host is alive, and runs the container or native jobs the client queues on the lease.

Sources: README.md, the module documentation of crates/js-lease-server/src/lib.rs and of crates/js-agent/src/lib.rs.

Install works today Linux x86_64 and arm64, and Apple silicon, from a release

$ gh release download vX.Y.Z -R komira-ai/jobscheduler -p 'js-lease-server-*-x86_64-unknown-linux-musl.tar.gz' -p SHA256SUMS

Every push to main that changes code that ships is released, with a checksum file and a build attestation. The install page has the steps, including how to verify the download.

A real run

Lease a host on one machine

This is a recording of one run on one machine: the lease server started from a file that lists one host, and the js client leasing that host, listing the lease and releasing it. There is no agent, so the host is held at once. The lease id and the expiry are as they were recorded.

# hosts.toml: one host, listed by hand; there is no agent
[[host]]
id = "gpu-01"
gpu_class = "nvidia-a100"

[host.resources]
cpu_millis = 64000
memory_bytes = 549755813888
gpus = 8

[host.capabilities]
isa = "x86-64-v3"
driver = "550"
$ printf 'a-local-token-of-at-least-32-bytes\n' > client-token && chmod 600 client-token
$ js-lease-server --state-file leases.toml --boot initialise --token-file client-token --pool-config hosts.toml &
$ js --server http://127.0.0.1:7300 --token-file client-token lease acquire --class gpu-host --gpus 1 --gpu-class nvidia-a100 --max-wall 1h
lease 1-1 host gpu-01 expires 1793614960284
$ js --server http://127.0.0.1:7300 --token-file client-token lease list
1-1 held host gpu-01 expires 1793614960284
$ js --server http://127.0.0.1:7300 --token-file client-token lease release 1-1
lease 1-1 freed
$ js --server http://127.0.0.1:7300 --token-file client-token lease list

cargo xtask site-demo in the repository builds both programs and runs these commands again; the recording is site/test/demo.transcript. The install page has the steps for a pool of agents.

What it does

A lease, an agent, a placement core

  • A lease is a host for a bounded time

    A client posts to /v1/leases with a class and a maximum wall time, renews the lease before its TTL lapses, and releases it. A client that disappears loses the lease at the end of its TTL.

  • An agent on every host

    js-agent offers the host's CPU, memory and GPUs, heartbeats, and runs container jobs on Linux (through Docker, Podman or crun) and native jobs on a Mac.

  • A whole node, quiet, when asked

    A whole-node lease books every dimension of one host, and its client gets the host only when nothing else is on it. A request that names a request id is queued, and one host is reserved and drained for it.

  • Placement by measured and predicted load

    The js-sched crate admits a lease to a worker when measured load plus predicted cost stays within the worker's CPU and memory. The lease server calls it only under --placement js-sched, to pick among the hosts with room by the hosts' load readings, then by how tightly a lease fits.

The concepts page says how each of these works and where it stops.
