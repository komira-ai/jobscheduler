A lease holds a host for a bounded time

A client asks POST /v1/leases for a class and resources. The server answers 201 with the host, or 202 pending when the provider has not confirmed the start. The client keeps the lease with POST /v1/leases/{id}/renew and ends it with DELETE /v1/leases/{id}. Every route but /healthz needs a bearer token.

Two limits end a lease. The TTL is what the client renews: 600s by default, at most 3600s unless the server's flags say otherwise. The maximum wall time is required in the request, and a renewal never extends the lease past its acquisition plus that time. A client that disappears loses the lease at the end of its TTL, never later than its maximum wall time.

# the shapes of the js client's commands
js lease acquire --class <class> --max-wall <dur> [--ttl <dur>] [--label k=v ...]
js lease renew <id> [--ttl <dur>]
js lease release <id>
js lease list
js lease run <the flags of acquire> -- <command> [args...]

js lease run acquires, starts the command with JS_LEASE_ID and JS_LEASE_HOST set in its environment, and renews while the command runs.

An acquire is not safe to retry blindly. When the answer is lost, the server may hold a lease the client has no id for. A client lists its leases and finds its own by the labels it sent before it asks again. An idempotency key, which would make a repeated acquire return the lease it made, is not built.

The server is single-tenant: there is one client token and so one trust domain, and whoever holds it can list, renew or release any lease. A token for each tenant is not built.

Hosts and pools

Capacity comes in pools. A pool has a name, a class, a shape and max_machines. The shape is what the pool books for every host: cpu_millis and memory_bytes, and optionally gpus, gpu_class and disk_bytes. Hosts reach a pool in one of three ways:

  • A static pool: the operator lists the hosts in a file.
  • Agents that join: an agent says hello with a join token, offers its CPU, memory and GPUs, and heartbeats. The pool file for them is --agent-pool-config.
  • An elastic pool: a provider launches machines for requests that wait. The provider kinds compiled in are static and lambdalabs. A pool's launch is plan, which launches nothing, unless the file says live; a live pool also has caps on instances and on spend per hour and per day.

memory_schedulable_percent is a whole number from 1 to 100, 100 by default. A pool books that share of each host's memory, rounded down.

A pool file names a class. The shipped classes are whole-node and gpu-host, which stays as an alias; any other name is a class that books a whole host too. not built A class that books only part of a host (a mixed pool) cannot be served: the server refuses the pool file with "a mixed pool (a class that books part of a host) is not served by this server yet".

A whole node: exclusive, quiet, reserved, capped

A whole-node lease is a class of its own, not a large request. It promises four things that a big share does not:

  1. Exclusive. It books every dimension of the host (CPU, memory, disk, all GPUs, all VM slots), and nothing else is placed on the host until it is released.
  2. Quiet. Before the client can use it the host has no run, no VM and no leftover of an earlier job, the post-job checks are clean and the host is not tainted.
  3. Reserved. A queued request is given exactly one host, by draining it, so a stream of small requests cannot starve it.
  4. Capped. Pool limits bound how many hosts are reserved or held whole.

Which host a reservation drains is decided by the drain cost: the latest end bound of the work on the host, then the fewest leases, then the lowest host id. A lease of this class is always answered 202 pending: it is listed pending until its host's agent reports it ready, then held, and it is dropped if that takes longer than the pool's prepare_timeout, ten minutes unless the pool file sets it.

A dedicated pool (class whole-node) lets every host be whole. The pool file's whole-node keys are max_whole_node, max_draining, max_whole_node_per_consumer, keep_for_ordinary, allow_last_capable, drain_after, drain_deadline, reserve_backoff, max_reserve_attempts, prepare_timeout, max_replace and regain_grace; gpu-host books a whole host without them and refuses them.

Sources: docs/design/whole-node.md (section 1, what it is), crates/js-agent/src/exclusive.rs (the agent reports ready only when no run is held, the post-job checks are clean and the host is not tainted), crates/js-whole/src/cost.rs (the drain cost), crates/js-whole/src/config.rs (the defaults), crates/js-lease-server/src/agent_pool.rs (the keys) and the API table of crates/js-lease-server/src/lib.rs (the 202).

Placement by CPU and memory

The placement core is js-sched, a pure state machine: it takes time as an input and reads no clock. It admits an action to a worker when what the worker's readings measure, plus the predicted cost of the leases no reading covers yet, plus the predicted cost of the new lease, stays within the worker's CPU and its memory, each charged at a cost the lease keeps from its grant to its result. The defaults plan a worker to 1.1 times its CPU (--placement-cpu-slack) and 1.0 times its memory. A worker with no usable reading is charged by predicted cost alone.

The cost comes from earlier runs of similar actions (js-sizing):

ResourceEstimate
Memoryround_up_256MiB(max(1.2 * M + 128 MiB, held, oom_floor)), where M is the largest uncensored sample of the last 256 or more runs, and at least 1 GiB
CPUround_up_250m(P90(cpu_usage / wall)), clamped to 250 m and the node's cores; 2000 m for a key with no CPU sample

A booking at or above the memory of the largest matching live node owns the host: the estimate never reaches a whole host, and the caller books cold instead.

Where it stops. not called by the lease server In js-lease-server, the code that would convert the server's vocabulary to the scheduler's exists and is used by tests alone; the file says "Nothing in the server calls them yet". A lease on a server you install today is placed by the pool, as above, and not by load. Mode off of the load rule is a rollback switch to the booked rule, and not a supported mode.

Sources: the module documentation of crates/js-sched/src/lib.rs (admission by load), crates/js-sched/src/admission/config.rs (the slack), crates/js-sizing/src/lib.rs (the estimates) and crates/js-sizing/src/summary.rs (COLD_CPU_MILLIS), crates/js-lease-server/src/sched/mod.rs (what the server calls).

A silent host

A host that goes silent keeps its lease and reads Unknown until it is heard again or the lease ends by its TTL or a release. The lease table frees a lease only when the provider is observed without it.
