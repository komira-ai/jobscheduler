Ask for a lease and print it

Usage: js lease acquire [OPTIONS] --class <CLASS> --max-wall <MAX_WALL>

Options:
      --class <CLASS>                The resource class, such as `gpu-host`
      --server <URL>                 The lease server, such as `https://leases.example:7300`. Plain `http://` is accepted for a loopback host only: the bearer token never crosses a network in clear. Required
      --gpus <GPUS>                  How many GPUs the request needs [default: 0]
      --token-file <PATH>            A file holding the bearer token: a regular file owned by you, mode 0600 or 0400. Required
      --ca-cert <PATH>               A PEM file with the certificate to trust for `https://` (the server's, or the authority that issued it); only those certificates are trusted then. Optional: without it an `https://` server is verified against the public roots bundled in the binary, never the platform's store, because the places it is found can be redirected by the environment
      --gpu-class <GPU_CLASS>        The GPU class the request needs, such as `nvidia-a100`
      --cpu-millis <CPU_MILLIS>      CPU, in thousandths of a core [default: 0]
      --json                         Print machine output (one JSON object per line, or the server's own JSON for `list`) instead of text; errors too
      --memory-bytes <MEMORY_BYTES>  Memory, in bytes [default: 0]
      --max-wall <MAX_WALL>          The longest the lease may last in all, such as `2h`
      --label <KEY=VALUE>            A label of the lease, `key=value`; repeat for more
      --validation-run <ID>          The validation run the lease serves
      --probe-host <HOST>            A probe: place the lease on this host alone, past its cordon (the server refuses it by name when the host is unknown, not cordoned, not serving, too small or not one the server can probe)
      --request-id <ID>              The request's id, of your choosing (1 to 63 of `a-z`, `A-Z`, `0-9`, `.`, `_`, `-`): an acquire repeated with the same id and flags answers the lease the first one made instead of taking a second, and a whole-node request waits for a host instead of being refused for lack of one. Every flag that shapes the request counts; `--wait-pending` does not. The same id with another request is refused `request-id-conflict` while the first lease is on the server
      --wait-pending <WAIT_PENDING>  How long to wait for a start the provider has not confirmed (202) to settle [default: 60s]
  -h, --help                         Print help
