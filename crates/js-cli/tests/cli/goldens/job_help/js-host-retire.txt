Retires the id of a lost host, so that its pool has room for a new id. Operator only. The host's row in the job store is deleted at the version read, with its stored binding and this server's record of it, so that neither the pool's count over the rows nor this server's own count holds the id any more: a host that changed its id (a host-certificate join after a token join with another id) can then join a pool at its max_machines. It is refused while the host is live (heard within the grace) or holds or is owed work (a job placed on it or ending on it, a taint, a cordon or a scale-down mark), each FAILED_PRECONDITION with its own code, and nothing is written. A host with nothing left to retire answers retired false and nothing is written, so a repeat is harmless; with several servers over one store, the same call on each forgets that server's record. The call does not reach the agent.

Usage: js host retire [OPTIONS] --host-id <TEXT>

Options:
      --server <URL>
          The server, such as `https://jobs.example:7300`. Plain `http://` is accepted for a loopback host only: the bearer token never crosses a network in clear. Required

      --token-file <PATH>
          A file holding the bearer token: a regular file owned by you, mode 0600 or 0400. Required

      --ca-cert <PATH>
          A PEM file with the certificate to trust for `https://` (the server's, or the authority that issued it); only those certificates are trusted then. Optional: without it an `https://` server is verified against the public roots bundled in the binary, never the platform's store, because the places it is found can be redirected by the environment

      --json
          Print machine output (one JSON object per line) instead of text; errors too

      --host-id <TEXT>
          The id of the host to retire.

  -h, --help
          Print help (see a summary with '-h')
