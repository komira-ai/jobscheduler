Writes a job's output to stdout as the job writes it, until the job has ended and every byte is written. Reads the stream with GetLogs from its first byte, each call asking the server to wait for new bytes and starting where the last one ended, so each byte is written once and exactly as the job wrote it. Bytes the log store does not hold are said on stderr. Exits 0 at the stream's end. After an answer with no new bytes js pauses a second; a follow the server refuses as busy is tried again after five seconds, and one whose answer is lost after two, three times in a row at most; any other failed call exits as any job command does. `js job logs` reads one page; this follows to the end. Written by hand, not generated from the job service.

Usage: js job follow [OPTIONS] --job-id <TEXT>

Options:
      --server <URL>
          The lease server, such as `https://leases.example:7300`. Plain `http://` is accepted for a loopback host only: the bearer token never crosses a network in clear. Required

      --token-file <PATH>
          A file holding the bearer token: a regular file owned by you, mode 0600 or 0400. Required

      --ca-cert <PATH>
          A PEM file with the certificate to trust for `https://` (the server's, or the authority that issued it); only those certificates are trusted then. Optional: without it an `https://` server is verified against the public roots bundled in the binary, never the platform's store, because the places it is found can be redirected by the environment

      --json
          Print machine output (one JSON object per line, or the server's own JSON for `list`) instead of text; errors too

      --job-id <TEXT>
          The id of the job whose output to follow.

      --stream <NAME>
          The stream to follow: stdout or stderr.
          
          [default: stdout]
          [possible values: stdout, stderr]

  -h, --help
          Print help (see a summary with '-h')
